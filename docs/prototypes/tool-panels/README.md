# 版本跟踪 V2 工具面板原型

直接用浏览器打开 `index.html`，无需安装依赖或启动开发服务器。左侧切换四个独立面板，面板上方的 **PROTOTYPE · 状态预览** 切换器可查看该面板的全部状态。原型使用 `versioning-v2-model.cjs` 中的同一份状态目录与业务规则；该文件同时可由浏览器和 Node 行为测试加载。

生产实现必须同时遵守 `docs/versioning-v2-contract.md`。本 README 是字段、状态和按钮行为的界面实现清单，不另行定义冲突的数据结构。

## 公共字段与行为

| 字段/控件 | 值 | 行为 |
| --- | --- | --- |
| 任意项目内文件夹 | 文件夹选择器；显示项目相对路径 | 不按名称过滤。外部快捷方式/重解析目录必须阻止移动和覆盖。 |
| 节点角色 | `original` / `progress` / `selection` | 普通首次来源登记为 original；主版本为 progress；选片输出为 selection。 |
| 关系类型 | `main` / `auxiliary` | main 在树上画实线；auxiliary 画虚线。提交显式字段，不能从 `versionKey` 推断。 |
| 父节点 | 节点 ID + 显示名 | 关系按 ID 写入。新的主版本只能选择主分支父节点；从 selection 入口进入时显示最近主分支祖先。 |
| 图片跟踪 | `trackingEnabled` | 仅 main 可用并持久化。关闭后另外两个选项同时归一为 false。 |
| 沿用上一版本文件名 | `renameFromParent` | 仅 main 且图片跟踪开启时可用并持久化。 |
| 补齐缺失媒体 | `copyMissingFromParent` | 仅 main 且图片跟踪开启时可用并持久化；父版本新增媒体会使该子节点 stale。 |
| 节点状态 | disabled / pending_compare / pending_confirm / committing / ready / stale / needs_repair | 文案严格使用契约映射；needs_repair 显示“需要修复”，不能显示“已跟踪”。 |

选择 `auxiliary` 后，三个跟踪选项立即禁用并显示原因，保存值强制全部为 false。选择 `main` 后恢复主分支选项。原型中的关系类型卡片可点击，用于直接检查该联动。

## 1. 新建进度

字段：

- 来源文件夹：任意项目内文件夹，用于确定主分支父节点。
- 新进度文件夹名：只作物理文件夹显示名，不参与关系判断。
- 主分支父节点：节点 ID 与显示名；不得选择 selection。
- 关系类型与三个跟踪策略字段。

状态：

- **准备**：填写字段，切换 main/auxiliary 并查看禁用说明。
- **处理中**：显示 `taskId`、`sessionId`、扫描计数、取消和“缩小到后台”。
- **结果**：展示节点状态、未覆盖文件计数和实线/虚线树结果。
- **失败**：展示短错误、任务/会话 ID，以及关闭、恢复面板、重试。

按钮：取消不写入；“新建并开始比较”先创建空进度并启动 compare；“缩小到后台”不取消任务；失败恢复继续对应 session。

## 2. 导入进度

字段：

- 任意项目内现有文件夹。
- 关系父节点、关系类型、三个跟踪策略。
- 非根目录移动预检摘要：来源、目标、快捷方式/重解析检测。

状态：

- **准备**：选择文件夹。非根目录 progress 明确提示下一步必须安全移动。
- **移动确认**：显示移动前后路径和外部链接检测；确认前不移动。
- **处理中**：compare 进度，可取消、可缩小到后台。
- **等待确认**：显示 recognized、pending_confirmation、missing_reference 数量；有未决定项目时禁止提交。
- **结果**：显示导入关系和不覆盖统计。
- **失败**：可恢复或重试；失败时不把大结果写入任务 metadata。

按钮：“继续并检查移动”只进入预检；“确认移动并继续”才安全移动；“确认并提交”必须等所有待确认/缺失引用项目处理完。

## 3. 修改进度

字段：

- 当前节点、主分支父节点、关系类型、三个持久化跟踪策略。
- stale 原因摘要：当前文件夹媒体变化，或父版本新增媒体且开启 `copyMissingFromParent`。

状态：

- **准备**：显示“待刷新”原因，允许仅保存策略或保存并刷新。
- **移动确认**：当修改使非根目录文件夹成为 progress 时，使用与导入相同的安全移动确认。
- **处理中**：refresh 返回 task/session 两个 ID，可缩小到后台。
- **等待确认**：refresh 比较结果仍必须逐项处理新素材。
- **结果**：提交完成后为 ready/“已跟踪”。
- **失败**：保留 session，任务中心可恢复面板。

按钮：“仅保存设置”不伪造 ready；“保存并刷新”启动 refresh；取消 refresh 回到刷新前状态；结果可打开版本树。

## 4. 确认跟踪图片

字段：

- `sessionId`、分页位置与项目总数。
- 每个项目的文件名、缩略信息、状态和用户决定。
- 项目状态：recognized、accepted、pending_confirmation、missing_reference、rejected。

状态：

- **载入结果**：按 sessionId 分页读取完整结果，可缩小到后台。
- **等待确认**：新素材显示“待确认”；支持“接受新素材”“拒绝”“重新定位”。
- **提交中**：状态 committing；按 sessionId 幂等提交，可缩小到后台。
- **结果**：显示确认、拒绝、跳过已有文件统计，并可回到版本树。
- **失败**：显示任务/会话 ID；可恢复面板或重试。

按钮规则：

- “确认并提交”在存在 `pending_confirmation` 或 `missing_reference` 时禁用。
- “保存并关闭”保留逐项决定，下次用同一 session 恢复。
- “缩小到后台”只关闭面板，不取消 compare/refresh/commit。
- 任务中心完成入口打开本面板对应 session；失败入口恢复本面板并显示短错误。

## 选片接入说明

选片本身不属于这四个版本面板，但生产选片界面必须复用契约：手动和文件名选片均显式选择一个来源文件夹；输出严格为同级 `来源文件夹名_选片`，节点是该来源的 auxiliary selection 子节点。图片、视频或混合媒体进入同一输出节点并保留相对子目录。重复选片只增量复制，绝不覆盖；目标被其他来源占用时以 `output_name_conflict` 阻止。不同父目录下的同名来源通过节点 ID 区分。

## 行为测试

在仓库根目录执行：

```powershell
node --test docs/prototypes/tool-panels/versioning-v2-model.test.cjs
```

测试执行真实模型函数，覆盖四面板状态目录、auxiliary 策略归一、状态文案、选片冲突、stale 传播、新素材确认门禁、task/session 协议和 tombstone 树重连；不是源码字符串 `includes` 测试。

### 确认预览规则

等待确认界面左侧保留完整项目列表，右侧显示所选项目的上一版本与当前版本。默认选中第一个 `pending_confirmation`，其次是 `missing_reference`，否则选中首项。接受、拒绝或重新定位后继续显示刚处理项目，并自动把选择移动到下一个未处理项目；普通上一项/下一项浏览可以经过已处理项目。

预览支持并排、叠加、交换、缩放和适合窗口。`missing_reference` 使用缺失占位，不制造引用图片；重新定位成功后才显示新的上一版本。新素材没有引用关系时明确显示“未关联上一版本”。选中项、预览模式、交换和缩放只属于渲染器状态，不写入数据库；数据库只保存项目状态和文件名关系。
