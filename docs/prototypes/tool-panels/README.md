# 版本跟踪 V2 工具面板原型

直接用浏览器打开 `index.html`，无需安装依赖或启动开发服务器。左侧切换五个独立面板，面板上方的 **PROTOTYPE · 状态预览** 切换器可查看该面板的全部状态。版本面板只创建或修改版本节点，用户不再选择底层关系类型。

生产实现必须同时遵守 `docs/versioning-v2-contract.md`。本 README 是字段、状态和按钮行为的界面实现清单，不另行定义冲突的数据结构。

## 公共字段与行为

| 字段/控件 | 值 | 行为 |
| --- | --- | --- |
| 任意项目内文件夹 | 文件夹选择器；显示项目相对路径 | 不按名称过滤。外部快捷方式/重解析目录必须阻止移动和覆盖。 |
| 节点用途 | 版本 / 原始素材 / 选片 / 预览产物 / 协作 | V1、V2、V1_1 都是可跟踪版本；JPG、mov_预览、选片和协作由各自入口创建。 |
| 父节点 | 节点 ID + 显示名 | 关系按 ID 写入，不依赖文件夹名称；只能选择有效原始素材或版本节点。 |
| 版本跟踪 | `trackingEnabled` | 仅版本节点可用。关闭后另外两个选项同时归一为 false。 |
| 沿用上一版本文件名 | `renameFromParent` | 仅版本跟踪开启时可用并持久化。 |
| 补齐缺失媒体 | `copyMissingFromParent` | 仅版本跟踪开启时可用并持久化；父版本新增媒体会使该子版本 stale。 |
| 节点状态 | disabled / pending_compare / pending_confirm / committing / ready / stale / needs_repair | 文案严格使用契约映射；needs_repair 显示“需要修复”，不能显示“已跟踪”。 |

关系语义由入口自动确定，面板不显示“关系类型”卡片。所有已保存关系在版本树中使用实线；RAW—JPG、MOV—mov_预览使用无箭头直线。V1_1 是正常版本分支，与 V2 一样支持跟踪、比较和提交。

准备态统一使用左右双栏：左侧显示文件夹、版本和父版本信息，右侧固定显示版本跟踪策略。图片与视频使用两个并列按钮选择，不使用下拉菜单；按钮切换后，示例名称和 RAW/MOV 父素材同步变化。

## 1. 新建进度

创建空的图片或视频版本文件夹。用户分别填写版本号与业务名称，不直接填写完整文件夹名；系统按 `图片后期_版本号_名称` 或 `视频后期_版本号_名称` 自动生成并实时预览。名称为空时生成 `图片后期_版本号` 或 `视频后期_版本号`。其余字段为来源位置、父版本和版本跟踪策略。选片与团片协作不在这里创建或勾选。

## 2. 创建下一版本

从版本树右侧输出端拖到普通文件夹后进入该流程。确认卡显示父版本、目标文件夹和刷新后计算出的版本号；默认创建下一主线版本，也可以明确创建 V1_1 这样的可跟踪版本分支。

提交前重新读取最新版本状态，避免多个任务同时使用同一版本号。

## 3. 导入进度

把项目内已有文件夹登记为版本节点。字段包括媒体类型、自动版本号、父版本和跟踪策略。非根目录文件夹先显示安全移动确认，确认前不移动；外部快捷方式不可登记。

## 4. 修改进度

修改版本名称、父版本和跟踪策略。版本文件夹改名必须从这里完成，以便同时更新物理路径、数据库记录和后代信息；普通文件重命名不承担这项职责。

“仅保存设置”不伪造 ready；“保存并刷新”启动 refresh。刷新失败时保留 session，可从任务中心恢复。

## 5. 确认跟踪图片

字段：

- `sessionId`、分页位置与项目总数。
- 每个项目的文件名、缩略信息、状态和用户决定。
- 项目状态：recognized、accepted、pending_confirmation、missing_reference、rejected。

状态：

- **载入结果**：按 sessionId 分页读取完整结果，可缩小到后台。
- **等待确认**：新素材显示“待确认”；支持“接受新素材”“拒绝”“重新定位”。
- **提交中**：状态 committing；按 sessionId 幂等提交，可缩小到后台。
- **结果**：显示确认、拒绝、跳过已有文件统计，并可回到版本树。
- **失败**：显示任务/会话 ID；可恢复面板或重试。

结果中的“当前版本链”只显示本次操作所在链路中已跟踪的原始素材和版本文件夹，使用 Git 分支树式轨道、节点和分叉线展示。选片、JPG、mov_预览和团片协作不进入这个列表。

按钮规则：

- “确认并提交”在存在 `pending_confirmation` 或 `missing_reference` 时禁用。
- “保存并关闭”保留逐项决定，下次用同一 session 恢复。
- “缩小到后台”只关闭面板，不取消 compare/refresh/commit。
- 任务中心完成入口打开本面板对应 session；失败入口恢复本面板并显示短错误。

## 选片、预览和协作

这些节点不通过版本面板创建或配置：选片节点只能由选片功能创建，JPG 和 mov_预览由素材/预览登记流程创建，团片协作只能由团片协作组件创建。团片协作以普通文件夹节点显示，并由组件根据实际参与素材记录来源关系。

## 行为测试

在仓库根目录执行：

```powershell
node --test docs/prototypes/tool-panels/versioning-v2-model.test.cjs
```

测试执行真实模型函数，覆盖五面板状态目录、版本策略归一、V2/V1_1 stale 传播、选片冲突、新素材确认门禁、task/session 协议和 tombstone 树重连；不是源码字符串 `includes` 测试。

### 确认预览规则

等待确认界面左侧保留完整项目列表，右侧显示所选项目的上一版本与当前版本。默认选中第一个 `pending_confirmation`，其次是 `missing_reference`，否则选中首项。接受、拒绝或重新定位后继续显示刚处理项目，并自动把选择移动到下一个未处理项目；普通上一项/下一项浏览可以经过已处理项目。

预览支持并排、叠加、交换、缩放和适合窗口。`missing_reference` 使用缺失占位，不制造引用图片；重新定位成功后才显示新的上一版本。新素材没有引用关系时明确显示“未关联上一版本”。选中项、预览模式、交换和缩放只属于渲染器状态，不写入数据库；数据库只保存项目状态和文件名关系。
